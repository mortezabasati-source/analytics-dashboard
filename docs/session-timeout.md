# مدیریت سشن‌های بی‌کار Streamlit

## رفتار برنامه

- پیش از هشدار، حرکت ماوس، کلیک، لمس، تایپ و اسکرول، مهلت بی‌کاری همان تب را تمدید می‌کنند.
- پس از **۵ دقیقه بی‌کاری**، یک مودال با شمارش معکوس ظاهر می‌شود. برای تمدید سشن باید روی «Fortsätt sessionen» کلیک کرد؛ حرکت ماوس یا Escape به‌تنهایی کافی نیست.
- پس از **مجموعاً ۱۰ دقیقه بی‌کاری** و بدون پاسخ، مرورگر با `location.replace` به یک سند HTML مستقل با نشانی `blob:` می‌رود. صفحهٔ Streamlit واقعاً unload می‌شود، وب‌سوکت بسته می‌شود و کد اتصال مجدد آن دیگر اجرا نمی‌شود.
- صفحهٔ پایان سشن هیچ اسکریپت، درخواست شبکه یا اتصال Streamlit ندارد. دکمهٔ «Starta en ny session» تنها با اقدام کاربر برنامه را دوباره باز می‌کند. مسیر اصلی، پیشوند reverse proxy و query string حفظ می‌شوند.
- متن رابط جدید، مطابق زبان فعلی داشبورد، سوئدی است.
- تایمر در پنجرهٔ اصلی مرورگر نصب می‌شود؛ اجرای مجدد Python یا بازسازی iframe توسط Streamlit آن را صفر نمی‌کند و listener یا تایمر تکراری نمی‌سازد. هر تب مهلت مستقل دارد و رویدادهای مصنوعی JavaScript فعالیت کاربر محسوب نمی‌شوند.

## تنظیم مدت‌ها

این دو متغیر محیطی بر حسب **ثانیه از آخرین فعالیت** هستند:

| متغیر | پیش‌فرض | کاربرد |
| --- | ---: | --- |
| `SESSION_IDLE_WARNING_SECONDS` | `300` | زمان نمایش هشدار |
| `SESSION_IDLE_TIMEOUT_SECONDS` | `600` | زمان پایان سشن، شامل مهلت هشدار |

مقادیر باید عدد صحیح و دارای شرط `0 < warning < timeout` باشند. برای نمونه:

```bash
export SESSION_IDLE_WARNING_SECONDS=300
export SESSION_IDLE_TIMEOUT_SECONDS=600
python -m streamlit run src/app.py
```

برای آزمایش دستی سریع می‌توانید به‌ترتیب `15` و `30` انتخاب کنید. در Cloud Run
متغیرها را در تنظیمات سرویس قرار دهید و revision جدید را با کد این شاخه منتشر کنید.
این تغییر وابستگی جدیدی به image تولید اضافه نمی‌کند؛ `COPY . .` فعلی فایل‌های
`src/assets/` را نیز کپی می‌کند.

## نصب ابزارهای تست

دستورات را از ریشهٔ مخزن اجرا کنید. Python 3.10، مطابق Dockerfile، مناسب است:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
```

در Linux، اگر کتابخانه‌های سیستمی مرورگر موجود نیستند:

```bash
python -m playwright install --with-deps chromium
```

نصب وابستگی‌های سیستم ممکن است دسترسی مدیریتی بخواهد. این ابزارها فقط برای توسعه
و تست هستند و `requirements.txt` تولید تغییری نکرده است.

## اجرای تست‌های سریع

```bash
python -m pytest -q --browser chromium --tracing retain-on-failure
```

تست‌ها سرور محلی Streamlit را روی پورت آزاد راه‌اندازی و در پایان متوقف می‌کنند.
همان `src/app.py` تولید اجرا می‌شود؛ فقط ماژول دیتابیس با دادهٔ قطعی آزمایشی جایگزین
می‌شود. فایل `.env`، دیتابیس واقعی و Cloud Run در این تست‌ها استفاده نمی‌شوند.

Playwright زمان مرورگر را جلو می‌برد تا بازه‌های واقعی **۳۰۰ و ۶۰۰ ثانیه‌ای تنظیمات**
بدون ده دقیقه انتظار بررسی شوند. تست‌ها آستانهٔ تولید را کوتاه نمی‌کنند و موارد زیر را می‌سنجند:

- زنده ماندن سشن و وب‌سوکت طی ۱۲ دقیقه با فعالیت ماوس، کیبورد یا کلیک؛
- نبود هشدار قبل از دقیقهٔ ۵ و نمایش هشدار در دقیقهٔ ۵؛
- ریدایرکت در دقیقهٔ ۱۰ و دریافت رویداد بسته شدن وب‌سوکت واقعی؛
- نبود اتصال مجدد خودکار در صفحهٔ پایان و شروع سشن جدید با کلیک؛
- تمدید صحیح سشن با پاسخ به هشدار، حتی پس از مهلت پایان قبلی؛
- صفر نشدن تایمر هنگام rerun یا رویداد مصنوعی؛
- جبران زمان گذشته پس از تعلیق تایمر و مستقل بودن دو تب.

برای مشاهدهٔ مرورگر از `--headed` استفاده کنید. trace شکست‌ها در `test-results/`
ذخیره می‌شود و با دستور زیر قابل بررسی است:

```bash
python -m playwright show-trace test-results/<test-directory>/trace.zip
```

## تست نهایی با ده دقیقه زمان واقعی

این تست از ساعت شبیه‌سازی‌شده استفاده نمی‌کند و به‌طور پیش‌فرض skip می‌شود:

```bash
python -m pytest -q --browser chromium --run-real-time -m real_time
```

اجرای آن حدود ده دقیقه طول می‌کشد و هشدار، ادامهٔ اتصال تا زمان انقضا، ریدایرکت و
بسته شدن وب‌سوکت را بررسی می‌کند. اجرای همهٔ تست‌ها، از جمله این مورد:

```bash
python -m pytest -q --browser chromium --run-real-time --tracing retain-on-failure
```

## نکات Cloud Run و محدودیت‌ها

این راهکار اتصال درخواست طولانی‌مدت همین تب را حذف می‌کند. طبق
[مستندات وب‌سوکت Cloud Run](https://docs.cloud.google.com/run/docs/triggering/websockets)،
وجود حتی یک وب‌سوکت باز می‌تواند instance را فعال نگه دارد. قطع اتصال یک تب،
به معنی خاموش شدن فوری instance نیست؛ تب‌های دیگر، درخواست‌های دیگر و تنظیمات
صورتحساب و حداقل instance نیز اثر دارند. برای امکان scale-to-zero، مقدار minimum
instances باید صفر باشد و سیاست صورتحساب متناسب با نیاز سرویس بررسی شود.
[مستندات autoscaling](https://docs.cloud.google.com/run/docs/about-instance-autoscaling)
جزئیات این رفتار را توضیح می‌دهد.

کم کردن request timeout خود Cloud Run معیار فعالیت کاربر نیست و به‌تنهایی جای این
مکانیزم را نمی‌گیرد؛ کلاینت Streamlit ممکن است پس از قطع شبکه دوباره وصل شود.

مرورگر می‌تواند تایمرهای تب پس‌زمینه را کند یا اجرای یک تب/فرایند کاملاً تعلیق‌شده
را متوقف کند. این پیاده‌سازی زمان مطلق را هنگام اجرای بعدی تایمر، بازگشت تب یا
اولین فعالیت بررسی می‌کند و سشن منقضی‌شده را تمدید نمی‌کند. **قطع دقیق در ثانیهٔ ۶۰۰
وقتی JavaScript کاملاً متوقف است تضمین نمی‌شود**؛ چنین تضمینی به تشخیص بی‌کاری و
قطع اتصال در سمت سرور یا یک پراکسی با پروتکل heartbeat فعالیت کاربر نیاز دارد.
این مکانیزم برای کنترل هزینه است و جایگزین احراز هویت یا logout امنیتی نیست.

کد با Streamlit پین‌شدهٔ پروژه، یعنی **1.41.0**، سازگار است. دسترسی component
به سند والد از سیاست iframe همین نسخه استفاده می‌کند؛ کد به آبجکت‌های خصوصی
WebSocket یا runtime داخلی Streamlit وابسته نیست.
[کد رسمی سیاست iframe در نسخهٔ 1.41.0](https://github.com/streamlit/streamlit/blob/1.41.0/frontend/lib/src/util/IFrameUtil.ts)
و [راهنمای ساعت Playwright](https://playwright.dev/python/docs/clock)
مراجع فنی این پیاده‌سازی هستند. هنگام ارتقای Streamlit یا افزودن CSP محدودکنندهٔ
اسکریپت‌های inline، تست‌های مرورگر را دوباره اجرا کنید.

## نتیجهٔ اعتبارسنجی این تغییر

در تاریخ ۲۰۲۶-۱۱-۰۲، با Python 3.10.20، Streamlit 1.41.0 و Chromium 141:

- تست‌های سریع نسخهٔ نهایی: **۹ موفق**، یک تست زمان واقعی به‌صورت پیش‌فرض skip شد؛ مدت اجرا ۲۶٫۵۶ ثانیه.
- اجرای جداگانهٔ تست با زمان واقعی: **۱ موفق**؛ مدت اجرا **۶۰۴٫۶۰ ثانیه**. نمایش هشدار، ریدایرکت و بسته شدن وب‌سوکت تأیید شدند.
- بررسی وابستگی‌ها با `pip check` و بررسی syntax پایتون نیز موفق بودند.

برای تکرار تست با ابزارهایی که در همین محیط آماده شده‌اند و بدون نصب سیستمی
کتابخانه‌های Chromium، پس از فعال‌سازی `.venv` این متغیرها را تنظیم کنید:

```bash
export PLAYWRIGHT_BROWSERS_PATH=/tmp/streamlit-timeout-browsers
export LD_LIBRARY_PATH=/tmp/streamlit-timeout-libs/extracted/usr/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
python -m pytest -q --browser chromium
```

این مسیرهای موقت فقط به محیط فعلی مربوط‌اند؛ برای محیط تازه از مراحل نصب بالا استفاده کنید.
